# Huffman implementation replacement

## Scope and preserved contract

Only the public candidate's Huffman component, interface documentation and
inspector tests change. The frozen release and service scripts are not changed.

The two public functions retain their signatures. Matching accepts exactly the
four default tables (DC/AC, IDs0/1), rejects nulls/other selectors/different
counts or symbols, and does not modify input. Callers supply16 count bytes and
symbol_count readable symbol bytes. Output appends four DHT segments in order
00,10,01,11, totaling432 bytes, without replacing the caller's prefix.

The inspector still invokes matching and the RTP JPEG reconstruction path still
invokes DHT output. JPEG validation, RTP wire rules, queues, ownership and session
management are not changed.

## New implementation design

The old array-and-memcmp implementation is replaced, not renamed or reformatted.
Specification parameters are separated into
`m4_rtp_jpeg_check/src/jpeg_standard_codebooks.hpp`: symbols grouped by code
length. Counts are derived from those groups.

A bounded catalog constructs canonical codewords (code bits, length, symbol).
The matcher validates histogram totals before accessing symbols, checks prefix
capacity and compares the resulting canonical sequence against that catalog.
Serialization derives a histogram from codeword records, builds a432-byte
local image, and appends it to the destination vector in one operation.
Catalog initialization is C++11 thread-safe and has no per-frame heap allocation.
The destination vector can allocate as before; no globally allocation-free claim
is made. Invalid built-in parameters cause a logic_error rather than emitting
a partial DHT. The original source was inspected for its contract; this is not
represented as a formally isolated clean-room exercise.

## Parameter and implementation sources

The grouped parameters were transcribed from the currently consulted
[RFC2435 Appendix B](https://www.rfc-editor.org/rfc/rfc2435.html) listing,
not generated by transforming the old project file. These are the JPEG default
Huffman parameters associated with JPEG/T.81 Annex K. No ITU/ISO document or
external codec implementation is bundled. The specification's example C routines
are not the implementation used here.

The canonical catalog/matcher/serializer are newly designed project code for
this revision. No claim about the historical author or source of the superseded
file is made, and its frozen hash remains in SOURCE_MAP only as an origin record.

The historical permission and its required notice are now retained in
[RFC2435 notice](../LICENSES/RFC2435-notice.txt), supported by the publication-era
policy and official Trust explanation described in [notices](../THIRD_PARTY_NOTICES.md).
The new project implementation is [MIT](../LICENSE); RFC-derived parameter
material retains its historical terms and is not relicensed as MIT. The old
unknown implementation is no longer proposed for distribution.

## Independent behavior evidence

The inspector test uses its own JPEG marker walker to extract DHT from the
included platform-encoded synthetic JPEG. It does not read the new parameter
header or use inspector reports for its expected DHT bytes. Checks include all
four exact tables, every individual histogram/symbol byte mutation, unsupported
selectors, null pointers, wrong symbol counts, duplicate symbols, oversized and
oversubscribed histograms, exact432-byte serialization, preserved prefix and
repeated append. All pre-existing inspector and RTP assertions remain.

Current host: Windows, native g++/MSYS tools. Six portable C++ checks passed,
including wire/packetizer/inspector and ownership/isolation. An independent
allowlisted clean-copy export repeated all six portable checks successfully.
Windows operational
subsets passed128/128 (service50, watchdog16, release18, stability24, dual-client20);
nine ABI-checker tests and shell syntax checks also passed. These subsets do not
include native POSIX installation/diagnostic tests. Subsequently the maintainer
reported native162/162, ABI-checker9/9 and Poky compile/link/static ABI PASS for
this replacement. Those results were not rerun in the notice review. The actual
replacement ARM SHA-256 supplied by the maintainer is
`8b631abafc478e21e23e755d2676f5061bde8292df16c5bc552c4e27e3e84f46`.
It was not recomputed here. Previous frozen hash equality applies only to the
pre-replacement candidate.

Run the complete non-deploying revision gate from a native Ubuntu shell without
an active SDK environment:

```bash
bash tools/validate_huffman_revision.sh
```

It performs an allowlisted independent native build, six CTests, actual JPEG
decode, full operational offline regressions, nine ABI-checker tests and the
separate fresh Poky compile/link/static ABI gate. Logs/build evidence are
retained by those tools. It does not contact or run anything on a board.
